#### A. Remote Control（远程控制）- 研究预览 ★★★ 重要遗漏

**状态**: 2026-02 Research Preview，Pro/Max 计划可用

允许从手机/平板/任何浏览器继续本地 Claude Code 会话：
- 命令 `claude remote-control` 启动，终端显示 QR 码
- 扫码后在 claude.ai/code 或 Claude iOS/Android App 中继续同一会话
- 保留完整的本地环境（.claude/ 配置、MCP、文件系统）
- 跨设备同步对话，终端/浏览器/手机可交替发消息
- 限制：每实例一个远程连接、终端需保持开启、10分钟网络超时

来源: [Remote Control Docs](https://code.claude.com/docs/en/remote-control), [Simon Willison Blog](https://simonwillison.net/2026/Feb/25/claude-code-remote-control/)

#### B. Plugin 系统 ★★★ 重要遗漏

**状态**: 正式发布

#### 重要遗漏的高级 Hook 能力 ★★★

**1. Hook 中的 Input Modification（updatedInput）**

PreToolUse 和 PermissionRequest Hook 可以**透明修改工具输入**：
- 通过 `updatedInput` 字段在工具执行前修改参数
- 实现透明沙盒（重写文件路径到 /sandbox/）
- 自动安全强制（添加 --dry-run 标志、密钥脱敏）
- 团队规范强制（commit message 格式化、linter 配置注入）
- 路径纠正、依赖自动安装等

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "updatedInput": {
      "command": "npm run lint --fix"
    }
  }
}
```

**guides 覆盖情况**: ❌ 完全遗漏，这是非常强大的能力

**2. Prompt-based Hooks（prompt 类型钩子增强）**

- Agent 类型 Hook（`type: "agent"`）可启动子代理做复杂验证，能用 Read/Grep/Glob 工具
- Prompt Hook 和 Agent Hook 支持 `model` 字段选择评估模型

**guides 覆盖情况**: 部分覆盖（提到了 prompt 和 agent 类型，但 agent hook 的工具访问能力未说明）

**3. HTTP Hooks 的 Header 环境变量插值**

```json
{
  "type": "http",
  "url": "http://localhost:8080/hooks/pre-tool-use",
  "headers": { "Authorization": "Bearer $MY_TOKEN" },
  "allowedEnvVars": ["MY_TOKEN"]
}
```

`allowedEnvVars` 白名单控制哪些环境变量可被插值。

**guides 覆盖情况**: ❌ 遗漏（HTTP Hook 仅一行示例）

**4. CLAUDE_ENV_FILE 环境变量持久化**

SessionStart Hook 独享的 `CLAUDE_ENV_FILE` 变量：
- 写入 `export` 语句到该文件，在整个会话的所有 Bash 命令中生效
- 适合 nvm use、虚拟环境激活等环境初始化
- 已知 Bug：resume 会话时 session ID 不匹配导致 env 文件路径错误

**guides 覆盖情况**: ❌ 完全遗漏

**5. Hooks in Skills/Agents Frontmatter**

Hook 可以直接写在 Skill 或 Agent 的 YAML frontmatter 中：
```yaml
---
name: secure-operations
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/security-check.sh"
---
```

作用域限定在组件生命周期内，组件完成后自动清理。

**guides 覆盖情况**: ❌ 遗漏（03-Skills 文档提到了 frontmatter 字段但没有 hooks 示例）

**6. `once` 字段**

Skill 中的 Hook 可设置 `"once": true`，每个会话只运行一次后自动移除。

**guides 覆盖情况**: ❌ 遗漏

### 1.4 SubagentStart Hook 的实际用途

官方文档确认：
- **匹配器**: 按 agent 类型名过滤（Bash、Explore、Plan、自定义 agent 名）
- **不能阻断**: 只能注入 `additionalContext` 到子代理上下文
- **典型用途**:
  - 向所有子代理注入安全策略（"Follow security guidelines for this task"）
  - 根据 agent 类型注入不同的上下文（如给 code-reviewer agent 注入 coding standards）
  - 监控/日志记录子代理启动

**guides 覆盖情况**: 仅列出事件名，缺少实际应用案例

---

### 1.5 Setup Hook 的实际应用场景

- 通过 `--init`、`--init-only`、`--maintenance` CLI 标志触发
- `--init`: 运行 Setup Hook + 启动交互会话
- `--init-only`: 运行 Setup Hook + 立即退出（适合 CI/CD）
- 典型用途：依赖安装、数据库初始化、环境配置
- 可配合 prompt 实现"确定性 + 智能体"组合：Hook 先运行脚本，Claude 再分析结果

**guides 覆盖情况**: 仅列出事件名，缺少 CLI 标志说明和实际用例

---

### 1.6 ConfigChange Hook 的实际用途

- 匹配器值：`user_settings`, `project_settings`, `local_settings`, `policy_settings`, `skills`
- **可阻断**（exit 2 阻止配置变更生效，但 policy_settings 除外）
- 典型用途：
  - 企业安全审计（防止配置篡改）
  - 检测 settings 文件的恶意修改
  - 配置变更日志记录

**guides 覆盖情况**: 仅列出事件名，缺少 matcher 值和使用场景

## 三、多 Agent 协作模式

### 3.1 Agent Teams 详细架构 ★★★

来源: [官方文档](https://code.claude.com/docs/en/agent-teams), [Addy Osmani 博客](https://addyosmani.com/blog/claude-code-agent-teams/)

**核心组件**：

1. **TeammateTool**: Claude Code 内置的 13 个操作的多 agent 编排系统
2. **任务系统**: 带依赖追踪的任务管理
3. **直接通信**: Teammate 之间可直接消息通信，无需通过 Lead 中转
4. **Worktree 隔离**: 每个 Teammate 自动使用独立 worktree

**Orchestrator + Worker 模式**：

社区已有人实现：
- [Claude Code Swarm Orchestration Skill](https://gist.github.com/kieranklaassen/4f2aba89594a4aea4ad64d753984b2ea) - 完整的多 agent 编排 Skill
- [ruflo](https://github.com/ruvnet/ruflo) - 企业级 agent 编排平台
- [overstory](https://github.com/jayminwest/overstory) - 多 agent 编排器，支持 Claude Code 等多种运行时

**最佳实践**：
- 3-5 个 Teammates 是最优平衡点
- Leader 创建 Plan → 分解任务分配给 Workers → Workers 创建 Worktree → 并行开发 → 自动化测试 → 合并
- 子代理 vs Agent Teams：子代理在单会话内只能向上汇报；Agent Teams 可以横向通信和自协调

**guides 覆盖情况**: 04 文档有基础介绍，但缺少 TeammateTool 细节、直接通信机制、Swarm Orchestration Skill 引用

# Claude Code 项目进度跟踪：社区方案调研

> 调研日期：2026-03-08
> 目的：解决"Claude Code 跨会话项目进度丢失"问题

---

## 问题本质

Auto Memory 擅长记住"偏好和纠正"，但不擅长跟踪"功能 A 做到 80%，功能 B 还没开始"。
旧系统的 CURRENT.md 虽然手动维护麻烦，但进度是可见的、结构化的。
新系统废弃了它，留下了进度跟踪的空白。

---

## 方案 1：Tasks API（原生内置）

**来源**: Claude Code v2.1.16+, [claudefa.st](https://claudefa.st/blog/guide/development/task-management), [VentureBeat](https://venturebeat.com/orchestration/claude-codes-tasks-update-lets-agents-work-longer-and-coordinate-across-sessions/)

**机制**：
- 四个工具：TaskCreate / TaskUpdate / TaskList / TaskGet
- 任务持久化在 `~/.claude/tasks/`，跨会话存活
- 支持 DAG 依赖关系（Task 3 可依赖 Task 1 和 Task 2）
- `CLAUDE_CODE_TASK_LIST_ID=my-project` 可让多会话共享任务列表
- `Ctrl+T` 切换任务面板

**优点**：零配置，原生支持，跨会话持久
**缺点**：偏向"会话级任务"，不是"项目路线图"；没有 Git 版本控制

---

## 方案 2：ROADMAP.md 联动（社区高人气）

**来源**: [Ben Newton](https://benenewton.com/blog/claude-code-roadmap-management)

**机制**：
- 在项目中维护 `ROADMAP.md`
- CLAUDE.md 中指示 Claude 每次会话先读取它
- 用 checkbox 协议标记进度

```markdown
## High Priority
- [x] ✅ 2026/02/15 完成 API 文档
- [-] 🏗️ 2026/03/01 重构数据库层
- [ ] 实现用户认证模块
```

`[ ]` 待办 / `[-]` 进行中（附日期） / `[x]` 完成（附日期）

**优点**：Git 版本控制，进度可见，简单直观
**缺点**：需要手动或让 Claude 更新

## 方案 3：Planning-with-files 三文件系统（评测最强）

**来源**: [planning-with-files](https://github.com/OthmanAdi/planning-with-files)

**核心理念**：Context Window = RAM（易失），Filesystem = Disk（持久）

三个文件：

| 文件 | 内容 |
|------|------|
| `task_plan.md` | 阶段、目标、checkbox 进度 |
| `findings.md` | 研究发现、关键信息 |
| `progress.md` | 会话日志、测试结果、错误记录 |

**评测数据**：使用此方案任务完成率 96.7%，不使用仅 6.7%

**优点**：有数据支撑，结构化好
**缺点**：三个文件维护成本较高，文件可能膨胀

## 方案 4：Project Memory（结构化知识库）

**来源**: [project-memory](https://github.com/SpillwaveSolutions/project-memory)

**机制**：在 `docs/project_notes/` 下维护四个标准文件：

- `bugs.md` — Bug 日志 + 解决方案
- `decisions.md` — 架构决策记录（ADR）
- `key_facts.md` — 项目配置、端口、URL
- `issues.md` — 工作日志 + ticket ID

Claude 遇到错误自动搜索 bugs.md，架构变更前自动检查 decisions.md。

**优点**：知识沉淀好，防止重复踩坑
**缺点**：偏向"知识管理"而非"进度跟踪"

---

## 方案 5：claude-mem（重型方案）

**来源**: [claude-mem](https://github.com/thedotmack/claude-mem)

**机制**：
- 5 个生命周期 Hook（SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd）
- 自动捕获会话活动，AI 压缩后存入 SQLite + Chroma 向量数据库
- 未来会话通过语义搜索注入相关上下文
- 约 10x token 节省

**优点**：全自动，语义搜索强大
**缺点**：依赖外部服务，配置复杂，过重

---

## 方案 6：CCPM — GitHub Issues 集成

**来源**: [ccpm](https://github.com/automazeio/ccpm)

**机制**：
- GitHub Issues 作为任务管理后端
- 结合 Git worktrees 实现并行 agent 执行
- 团队成员可在 Issue 评论中看到 AI 实时进度

**优点**：天然适合团队协作，进度对外可见
**缺点**：个人项目过重，依赖 GitHub

## 其他社区实践

### Session Memory（原生自动）
- Claude Code 自动提取会话摘要，存储在 `~/.claude/projects/<hash>/<session>/session-memory/summary.md`
- 10,000 token 后首次触发，后续每 5,000 token 更新
- `claude --continue` 恢复最近会话
- `claude --resume <session-id>` 恢复指定会话

### CLAUDE.md 精简化共识
- 只放每次会话都需要的内容
- 从 Claude 犯错的地方开始写，而非穷举
- 控制约 13KB 以内
- 给每个工具分配"token 预算"
- 避免 `@` 引用大文件（会膨胀 context）

**来源**: [cuong.io](https://cuong.io/blog/2025/06/15-claude-code-best-practices-memory-management), [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature)

## 推荐组合方案

**方案 2（ROADMAP.md） + 方案 1（Tasks API）**：

1. `ROADMAP.md` — 项目级进度（Git 版本控制，持久可见）
2. CLAUDE.md 加 `@docs/ROADMAP.md` — 每次会话自动加载
3. 改造 `/handoff` Skill — 交接时同步更新 ROADMAP.md checkbox
4. Tasks API（`Ctrl+T`） — 会话内细粒度任务管理

**分工**：
- 项目级进度 → ROADMAP.md（持久、可见、有版本控制）
- 会话级任务 → Tasks API（原生、轻量）
- 交接时自动更新 → /handoff 改造

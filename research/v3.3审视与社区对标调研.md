## 一、v3.2/v3.3 设计验证

### 1.1 ROADMAP 项目进度跟踪（v3.2）

**我们的设计**: `docs/roadmap/` 目录，按 Phase 拆分文件，handoff 自动更新 checkbox，catchup 读取恢复进度。

**社区验证**:
- [CCPM (Claude Code Project Manager)](https://github.com/automazeio/ccpm) — 使用 GitHub Issues + Git worktrees 做项目管理
- [claude-roadmap-commands](https://github.com/arach/claude-roadmap-commands) — 专门的 roadmap 管理命令
- 社区标准化进度跟踪约定：`[ ]` Todo、`[-]` In Progress（带时间戳）、`[x]` Completed（带时间戳）
- 核心原则："Never let Claude write code until you've reviewed and approved a written plan"

**结论**: ✅ 方向正确，与社区主流对齐。我们的 checkbox + Phase 文件方案更轻量，适合个人和小团队。

### 1.2 /spec 设计文档系统（v3.3）

**我们的设计**: `docs/specs/` 目录 + `/spec` Skill，将需求讨论成果持久化为结构化设计文档，支持增量更新，状态生命周期：草稿→已确认→实施中→已完成。

**社区验证**:
- [Martin Fowler: Understanding Spec-Driven-Development](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html) — SDD 已成 2026 主流趋势
- [GitHub spec-kit](https://github.com/github/spec-kit) — GitHub 官方开源的 SDD 工具包，工作流：Define principles → Define requirements → Create plan → Break into tasks → Implement
- [claude-code-spec-workflow](https://github.com/Pimzino/claude-code-spec-workflow) — 专门的 Claude Code spec 工作流
- [Addy Osmani: How to write a good spec for AI agents](https://addyosmani.com/blog/good-spec/) — spec 写作最佳实践
- [arxiv 论文: Spec-Driven Development](https://arxiv.org/abs/2602.00180) — 学术界也在研究
- 早期采用者报告：多代理工作流结合 spec 可实现 10-50% 更快的交付周期

**结论**: ✅ 高度对齐。我们的方案比 spec-kit 更轻量（不依赖外部工具），适合 Claude Code 原生工作流。spec-kit 可作为参考/替代方案。

### 1.3 上下文管理策略

**我们的设计**: Document-and-Clear 模式（handoff → clear → catchup），70% 阈值主动处理。

**社区验证**:
- [Managing Context Window: Clear vs. Compact](https://medium.com/@nustianrwp/managing-your-context-window-clear-vs-compact-in-claude-code-8b00ae2ed91b) — 社区强烈推荐 Document-and-Clear 优于 /compact

- [Claude Code Decoded: The Handoff Protocol](https://blackdoglabs.io/blog/claude-code-decoded-handoff-protocol) — "10,000+ token knowledge transfer → 1,000-2,000 token resume operation"
- 社区共识："compact 不透明、易丢关键信息"；"/clear + 外部文档 = 可控、可读的持久记忆"

**结论**: ✅ 完全一致。我们的 handoff/catchup 双 Skill 设计是社区主流模式的系统化实现。

### 1.4 CLAUDE.md 规范

**我们的设计**: < 150 行根文件，MUST/MUST NOT 语言，@ 引用外部文件。

**社区验证**:
- [How to Write a Good CLAUDE.md](https://www.builder.io/blog/claude-md-guide) — 建议 50-100 行 + @imports
- 官方建议：150-200 instructions 上限（系统 prompt 已占约 50）
- 社区黄金法则："Tell it why, not just what"
- "CLAUDE.md is as important as .gitignore — essential infrastructure, not optional documentation"
- "If it's a suggestion, use CLAUDE.md. If it's a requirement, use hooks."

**结论**: ✅ 一致。可补充 "说明 why 而不只是 what" 的建议到 01 内容规范。

## 二、发现的差距

### 2.1 高优先级（影响准确性）

#### 2.1.1 02-Hooks 事件列表不完整

我们的 02 文档列了约 14 个事件，但 [官方 Hooks Reference](https://code.claude.com/docs/en/hooks) 现在包含更多：

**我们缺少的事件**:

| 事件 | 触发时机 | 用途 | Handler 类型 |
|------|---------|------|-------------|
| `SessionEnd` | 会话终止时 | 清理资源、记录会话统计 | command only |
| `PermissionRequest` | 权限请求时 | 编程化自动审批/拒绝权限请求 | command, prompt, agent |
| `PostToolUseFailure` | 工具执行失败时 | 错误处理、自动重试逻辑 | command, prompt, agent |
| `SubagentStart` | 子代理启动时 | 监控子代理生命周期 | command only |
| `Setup` | --init/--init-only/--maintenance 触发 | 仓库初始化和维护 | command only |

**另外缺少的特性**:
- **Async hooks**（2026-01 发布）：hooks 可以后台异步执行，不阻塞 Claude。这对性能敏感的 hook（如通知、日志）很有价值。

**来源**: [Hooks reference - Claude Code Docs](https://code.claude.com/docs/en/hooks)

#### 2.1.2 04-MCP 章节缺少 Tool Search 懒加载

**现状**: 我们的 04 文档警告"每个 MCP 服务器的工具定义会在每次请求时加载到上下文中"。

**更新**: Claude Code 新增 **MCP Tool Search** 功能，当工具描述超过上下文 10% 时自动启用按需加载，减少高达 95% 的上下文占用。这大幅缓解了 MCP 的上下文成本问题。

**来源**: [Connect Claude Code to tools via MCP](https://code.claude.com/docs/en/mcp)

#### 2.1.3 Context7 安装命令更新

**现状**: 我们写的是 HTTP transport 方式 `claude mcp add --transport http context7 https://mcp.context7.com/mcp`

**更新**: 社区普遍使用 npx 方式：`claude mcp add context7 -- npx -y @upstash/context7-mcp@latest`

两种方式都有效，但 npx 方式是最新推荐。

### 2.2 中优先级（有价值的补充）

#### 2.2.1 /loop 命令和 Cron 调度（全新功能）

2026-03 新增的 bundled skill，支持定时重复执行 prompt：

```bash
/loop 5m /audit --quick       # 每 5 分钟快速检查
/loop 1h check the deploy     # 每小时检查部署状态
```

特性：
- 支持 s/m/h/d 时间单位
- CronCreate 支持标准 5 字段 cron 表达式
- 定时任务自动 3 天后过期
- CLI 中的 /loop 是会话级的（退出后停止）
- Desktop 版的 scheduled tasks 是持久的（跨重启）

**来源**: [Run prompts on a schedule](https://code.claude.com/docs/en/scheduled-tasks)

#### 2.2.2 自定义子代理 .claude/agents/ 扩展

我们在 04 简单提了，但社区有大量实践：

- `/agents` 命令可以交互式创建子代理（选择 "Generate with Claude"）
- 用户级代理：`~/.claude/agents/`（所有项目可用）
- 项目级代理：`.claude/agents/`（项目专属）
- 工具访问控制：read-only（Read, Grep, Glob）、research（+WebFetch, WebSearch）、code writer（+Write, Edit, Bash）
- Description 决定 Claude 何时自动委派任务
- 无需重启即可使用

**来源**: [Create custom subagents](https://code.claude.com/docs/en/sub-agents), [awesome-claude-code-subagents](https://github.com/VoltAgent/awesome-claude-code-subagents)

#### 2.2.3 PermissionRequest Hook

可以编程化地自动审批或拒绝权限请求，对企业场景特别有价值：

```json
"PermissionRequest": [
  {
    "hooks": [
      {
        "type": "command",
        "command": "bash .claude/hooks/auto-approve.sh"
      }
    ]
  }
]
```

**来源**: [Hooks reference - Claude Code Docs](https://code.claude.com/docs/en/hooks)

#### 2.2.4 Plan Mode Ctrl+G 编辑

在 Plan Mode 中按 Ctrl+G 可以在编辑器中打开 plan，直接删除不需要的步骤、添加注释调整方案。

**来源**: [Plan Mode in Claude Code](https://codewithmukesh.com/blog/plan-mode-claude-code/)

### 2.3 低优先级（锦上添花）

#### 2.3.1 CLAUDE.md "说明 why 而不只是 what"

社区建议：
- "Use TypeScript strict mode" 是可以的
- "Use TypeScript strict mode because we've had production bugs from implicit any types" 更好
- why 给 Claude 在未预料场景中做判断的上下文

**建议**: 加到 01 内容规范 4.1 节。

#### 2.3.2 spec-kit 作为参考

GitHub 官方的 spec-kit 是 SDD 的标准化工具，工作流与我们的 /spec 高度一致。可在 research 文件中记录，不需要改主文档。

#### 2.3.3 PostToolUseFailure Hook

工具执行失败时触发，输入包含 `error` 和 `is_interrupt` 字段。可用于自动错误恢复。实用但非必需。

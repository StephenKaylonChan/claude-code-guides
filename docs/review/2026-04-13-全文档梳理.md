## 02 — Hooks 自动化配置

### 联网搜索关键发现（2026-04-13）

**Hook 事件 21→26 个**，新增 5 个事件：
- PermissionDenied — Auto mode 拒绝工具调用后
- StopFailure — API 错误结束时（rate_limit/auth_failed 等）
- CwdChanged — Claude 切换工作目录时
- FileChanged — 监视的文件变化时
- TaskCreated — 任务创建时

**Handler 类型支持大幅变化**：
- "仅 command"从 11 个事件缩减到 2 个（SessionStart、InstructionsLoaded）
- 其余全部升级支持 4 种 handler（command/http/prompt/agent）

**新增字段**：`if`（精细命令过滤）、`statusMessage`（自定义 spinner）、`shell`（bash/powershell）、`timeout`（自定义超时）

**CLAUDE_ENV_FILE** 从仅 SessionStart → 3 个事件（+CwdChanged、+FileChanged）

**超时区分**：command=600s, http/prompt=30s, agent=60s, SessionEnd=1.5s

**其他**：PreToolUse 新增 `defer` 决策值、Stop hook 新增 `stop_hook_active` 防循环、InstructionsLoaded 支持 matcher（load_reason）、Elicitation/ElicitationResult matcher 对象为 mcp_server_name

### 优化点 10：Section 1 概述更新

**原因**: 核心价值和选择表引用旧方案（Slash Commands），且只讲好处不讲风险，用户配了一堆 Hook 后频繁遇到 error。

**优化方向**: 删旧方案引用，补充"渐进式配置"建议（从 1-2 个核心 Hook 起步），预警常见风险。

### 优化点 11：Section 2 事件清单全面更新

**原因**: 事件总数过时（21→26），Handler 类型支持矩阵严重过时（仅 command 从 11→2），InstructionsLoaded/Elicitation 等事件信息不完整。

**涉及内容**: 补 5 个新事件、更新 Handler 类型支持矩阵、InstructionsLoaded 补 matcher 和 load_reason 值、Elicitation/ElicitationResult 补 matcher 对象。

### 优化点 12：Section 3 Handler 类型更新

**原因**: 缺少各 handler 类型默认超时区分、缺少新字段（if/statusMessage/shell/timeout）、缺少 defer 决策值。

**优化方向**: 区分超时、补新字段、补 defer、模板中推荐 `if` 字段替代 matcher+脚本内过滤。

### 优化点 13：Section 4 补充 stdin 调试技巧

**原因**: stdin 示例只覆盖 PreToolUse/PostToolUse，其他事件格式不同，用户写脚本时猜错字段导致 jq 解析 error。

**优化方向**: 在 stdin 示例旁补"查看真实 stdin 格式"的调试一行代码。

### 优化点 14：Section 5 模板更新

**原因**: 旧方案引用、pre-commit-check 触发过宽（每次 Bash 都触发）、on-stop.sh 缺防循环检查、UserPromptSubmit 缺新能力、模板没有分优先级。

**优化方向**:
- 删旧方案引用
- pre-commit-check 用 `if: "Bash(git commit *)"` 替代 matcher+脚本过滤
- on-stop.sh 补 `stop_hook_active` 检查
- UserPromptSubmit 补 sessionTitle/decision:block
- 模板分层：推荐必配（SessionStart + Stop）vs 按需可选（其余）

### 优化点 15：Section 6 高级能力更新

**原因**: CLAUDE_ENV_FILE 支持事件过时（1→3）、Frontmatter Hooks 缺新字段、updatedInput 并发行为未说明。

**优化方向**: CLAUDE_ENV_FILE 补 CwdChanged/FileChanged、Frontmatter 补 if/statusMessage/shell、updatedInput 补并发警告。

### 优化点 16：Section 7 完整配置示例同步更新

随前面所有更新同步修改示例。

### 优化点 17：Section 8-9 性能和调试更新

**原因**: 超时信息笼统（统一写 10 分钟，实际各 handler 不同），调试章节缺已知 bug。

**优化方向**: Section 8 区分 handler 超时 + 补 timeout 自定义字段，Section 9 补已知 bug（长会话 hooks 停止执行、多并行实例 CPU 挂起）。
